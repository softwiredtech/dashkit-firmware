# Single source of truth for the CAN messages this system cares about.
# Consumed by tools/gen_dbc.py to emit main/can/dbc/dbc_generated.{c,h}.
#
# Columns (whitespace separated):  NAME  BUS  ROLE
#   BUS  = 0 (chassis / party) or 1 (vehicle) -- the physical bus the frame
#          rides on.
#   ROLE = decode : firmware decodes this message's signals on-device (full
#                   signal table emitted -- costs flash).
#          filter : firmware does NOT decode it; the frame reaches the DashPilot
#                   app over BLE while the app hasn't sent its own CAN filter.
#                   No signal table is emitted.
# Both buses are received in full, so the number of entries is not limited by
# the MCP251xFD's 32 filters.
#
# Every NAME must exist in dbc/bus_1_tesla_vehicle.dbc.
# Keep decode entries tight: every decoded message costs flash.
#
# The `filter` set mirrors what the DashPilot bridge mapper reads per bus
# (dashpilot/bridge/car/cars/tesla.h, TeslaDashKitMapper), so the app needs no
# CAN filter of its own.
